## Issues Encountered & Solutions

### 1. GraphQL Code Generation Path Issue

**Problem**: `codegen` script failed because `schema.graphql` path was relative to `packages/core` directory:
Error: Unable to find any GraphQL type definitions for the following pointers:

- schema.graphql

**Root Cause**: The `codegen` script in `packages/core/package.json` was running from the core directory, but `schema.graphql` is located at the monorepo root.

**Solution**: Updated the `codegen` script to run from the monorepo root:

```json
{
  "scripts": {
    "codegen": "cd ../.. && graphql-codegen --config codegen.yml"
  }
}
```

### 2. TypeScript Composite Project Declaration Error

**Problem**: `build:esm` failed with error:
error TS6304: Composite projects cannot disable declaration emit.

**Root Cause**: `tsconfig.esm.json` had `"declaration": false` while the base config had `"composite": true`.

**Solution**: Removed declaration disabling from `tsconfig.esm.json` and configured separate output directory:

```json
{
  "extends": "./tsconfig.json",
  "compilerOptions": {
    "module": "ES2022",
    "moduleResolution": "bundler",
    "outDir": "./dist-esm"
  }
}
```

### 3. ESLint Pre-commit Hook Failure

**Problem**: Unused import `ValidationErrorType` causing ESLint error:
packages/core/src/index.ts
8:3 error 'ValidationErrorType' is defined but never used @typescript-eslint/no-unused-vars

**Solution**: Removed the unused type import:

```typescript
// Before
import type {
  MatchStatus,
  Tournament,
  Match,
  ValidationError as ValidationErrorType, // ❌ Unused
} from './types';

// After
import type { MatchStatus, Tournament, Match } from './types';
```
