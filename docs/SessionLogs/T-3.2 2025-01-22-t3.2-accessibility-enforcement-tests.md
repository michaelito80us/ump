## Issues Encountered & Solutions

### 1. TypeScript Configuration Conflicts

**Problem**: Initial TypeScript errors in `packages/ui/tsconfig.json` indicating missing type definitions:
error TS7016: Could not find a declaration file for module 'jest-axe'
error TS2339: Property 'toHaveNoViolations' does not exist on type 'JestMatchers

**Root Cause**: The main `tsconfig.json` was incorrectly configured with test-specific types, and test files were using the wrong TypeScript configuration.

**Solution**:

1. Cleaned up `tsconfig.json` to focus only on library compilation
2. Updated `tsconfig.test.json` to include proper test types
3. Configured Jest to use the test-specific TypeScript configuration

### 2. Module Resolution Issues with Component Imports

**Problem**: Test files couldn't resolve component imports using `@/` alias:
error TS2307: Cannot find module '@/components/Button'

**Root Cause**: Jest's `moduleNameMapper` wasn't properly configured for the TypeScript compilation context.

**Solution**: Updated test files to use relative imports instead of the `@/` alias:

```typescript
// Before
import { Button } from '@/components/Button';

// After
import { Button } from '../components/Button';
```

### 3. Global Object TypeScript Errors in Setup File

**Problem**: TypeScript couldn't find the `global` object in the test setup:
error TS2304: Cannot find name 'global'

**Root Cause**: The test environment wasn't properly configured for Node.js global objects.

**Solution**: Used `Object.defineProperty(window, ...)` instead of `global` for browser API mocks:

```typescript
// Before
(global as any).IntersectionObserver = jest.fn()...

// After
Object.defineProperty(window, 'IntersectionObserver', {
  writable: true,
  value: jest.fn().mockImplementation(() => ({...}))
});
```

### 4. Jest-Axe Type Definitions Missing

**Problem**: TypeScript couldn't find proper type definitions for jest-axe matchers.

**Root Cause**: Missing `@types/jest-axe` package and improper configuration.

**Solution**:

1. Installed `@types/jest-axe` package
2. Added `jest-axe` to the types array in `tsconfig.test.json`
3. Used `jest-axe/extend-expect` for automatic matcher extension

## Key Learnings

1. **Separation of Concerns**: Main `tsconfig.json` should focus on library compilation, while `tsconfig.test.json` handles test-specific configurations.

2. **Jest-Axe Integration**: Using `jest-axe/extend-expect` provides cleaner setup than manual `expect.extend()` calls.

3. **Browser API Mocking**: `Object.defineProperty(window, ...)` is more reliable than `global` assignments in Jest/TypeScript environments.

4. **Import Strategy**: Relative imports are more reliable than path aliases in test environments.
