# T-13.2 ESLint Configuration Fixes - 2025-01-17

## Session Overview

This session focused on resolving ESLint configuration issues that were preventing successful commits due to pre-commit hook failures.

## Issues Addressed

### 1. ESLint `no-undef` Errors in Mobile App

**Problem**: Multiple browser globals were undefined in mobile app files during lint-staged execution:

- `CloseEvent`
- `MessageEvent`
- `Navigator`
- `ServiceWorkerRegistration`
- `MessageChannel`
- `IDBDatabase`
- `IDBVersionChangeEvent`
- `IDBOpenDBRequest`
- `EventListenerOrEventListenerObject`

**Root Cause**: lint-staged runs ESLint from the project root using the shared configuration (`eslint.config.shared.js`), but these browser globals were only defined in the mobile app's specific ESLint configuration.

**Solution**: Added missing browser globals to the shared ESLint configuration file.

### 2. Mobile App ESLint Configuration Issues

**Previous Issues Resolved**:

- Renamed `eslint.config.js` to `eslint.config.mjs` to prevent TypeScript processing
- Removed duplicate key entries in globals section
- Cleaned up duplicate browser global definitions

## Files Modified

- Added IndexedDB globals: `IDBDatabase`, `IDBVersionChangeEvent`, `IDBOpenDBRequest`, `EventListenerOrEventListenerObject`

### `apps/mobile/eslint.config.mjs` (Previously Modified)

## Key Learnings

1. **lint-staged Behavior**: lint-staged executes ESLint from the project root, using the root/shared configuration rather than package-specific configurations.

2. **Global Scope Management**: Browser globals need to be defined in the shared configuration to be available across all packages during pre-commit hooks.

3. **Configuration Hierarchy**: Package-specific ESLint configurations are used during development and direct ESLint execution, but shared configuration takes precedence during lint-staged execution.
